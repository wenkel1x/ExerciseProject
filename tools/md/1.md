### Linux 远程切换为windows方法
```sh
vim /etc/default/grub
GRUB_DEFAULT=saved

apt-get update grub
reboot_to_windows ()
{
  windows_title=$(grep -i windows /boot/grub/grub.cfg |cut -d "'" -f 2)
  sudo grub-reboot "$windows_title" && sudo reboot
}
reboot_to_windows
```

```shell 
sudo apt-get install sysfsutils
```
2. 查看当前调节器
```shell 
cat /sys/devices/system/cpu/cpu0/ cpufreq/scaling_governor 
```
3. 关闭ondemand服务
```shell 
systemctl stop ondemand
systemctl disable ondemand
```
4. 然后更改sysfutils启动文件/etc/sysfs.conf
```shell
vim /etc/sysfs.conf #有多少   CPU，就添加对应数量的代码，并更改为对应的CPU编号
devices/system/cpu/cpu*/cpufreq/   scaling_governor = performance
```

### auth log report Unit suspend.target is masked

通常是由于系统尝试进入挂起（suspend）状态，但该目标（suspend.target）已被 mask（屏蔽）所导致。这种情况常见于服务器或笔记本电脑被配置为禁止挂起，但系统组件（如 systemd-logind）仍尝试触发挂起操作。
* systemd-logind 会根据电源事件（如合上笔记本盖）尝试挂起系统。
* 如果你通过以下命令屏蔽了挂起目标,那么系统就无法再进入这些状态，但 logind 仍然尝试执行，导致日志中不断出现错误信息。
```shell
sudo systemctl mask suspend.target sleep.target hibernate.target hybrid-sleep.target
```
修改 logind.conf 配置,这样可以防止 logind 继续尝试挂起系统，从而避免日志被刷爆。
```shell
sudo nano /etc/systemd/logind.conf
#找到或添加以下行，并取消注释（去掉 #）
HandleLidSwitch=ignore
HandleLidSwitchDocked=ignore
HandleSuspendKey=ignore
HandleHibernateKey=ignore
#保存并退出，然后重启 logind 服务：
sudo systemctl restart systemd-logind
```

### Linux raid hard drive damage recovery
在 Linux 系统中，如果你使用的是 RAID 1（镜像模式），当其中一块硬盘损坏时，RAID 阵列仍然可以正常工作，但你需要尽快更换损坏的硬盘并重建阵列以恢复冗余。以下是重建 RAID 1 的标准步骤（以 mdadm 工具为例）：

步骤一：确认 RAID 阵列状态
```
cat /proc/mdstat
```
或者：
```
mdadm --detail /dev/md0
```

查看哪个磁盘已经失败（例如 /dev/sdb）。

步骤二：移除损坏的磁盘
```
mdadm /dev/md0 --fail /dev/sdb
mdadm /dev/md0 --remove /dev/sdb
```

步骤三：更换硬盘并分区（如果是新硬盘）
插入新硬盘后，使用 fdisk 或 parted 创建分区，并设置为 RAID 类型（代码为 fd）：
```
fdisk /dev/sdb
```
步骤四：将新硬盘加入 RAID 阵列
```
mdadm /dev/md0 --add /dev/sdb1
```

步骤五：查看重建进度
```
watch cat /proc/mdstat
```
你会看到类似：

[>....................]  recovery =  5.0% (123456/2345678) finish=30.0min speed=12345K/sec
步骤六：更新 mdadm.conf（可选）
如果你使用的是静态配置文件：
```
mdadm --detail --scan >> /etc/mdadm/mdadm.conf
```
